# 专利蒸馏 · 文风

只蒸写法。样本里的技术方案、参数、件号、产品名、权要句子都不写入文风文件。

## 前提

样本是本批申请文件。`samples_confirmed` 在用户点头前保持 `false`，文风 `status` 保持 `draft`。`style.kinds` 为 `application`。同一专利类型的多份申请合并成这一份文风。

## 要写的文件

`style.md` 用这四节，写完删掉 TODO：

1. 适用范围：专利类型、文书种类、行业（未确认就写建议，不要写成已定行业）。
2. 章节习惯：背景是否先写问题、实施方式先总后分、权要是否短句、附图说明是否按图号逐张。多份申请都出现的习惯写入正文；只在一份里出现的习惯单独标成「不稳定」。
3. 忌语与节奏：句长、是否先效果后结构、禁用的广告腔。用抽象说法，例如「避免绝对化效果」，不要引用样本原句。
4. 不写入的事实：声明本文件不含样本技术内容。

章节片段：

`sections/application.md` 分节：背景、权要口气、实施方式、附图。外观把简要说明和视图命名写在这一页。多份申请的共同习惯写在对应节里。

`samples.md` 只列表：路径、角色。每条 `inputs.path` 都要出现。不粘贴全文。

## 不要做

- 不要把点×权要表写进 `style.md`。
- 不要把文风写成下一案可以直接粘贴的段落。
- 用户未确认前不要把 `style.status` 改成 `confirmed`。
