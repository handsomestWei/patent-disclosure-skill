# 申请文件 · 总则

## 定位

已有交底包时，写出权利要求书、说明书、说明书摘要、说明书附图。交底提供技术方案事实；说明书按申请书式撰写。Word 可再转 PDF。

主交付：权利要求书、说明书、说明书摘要、说明书附图（含摘要附图，通常复用主流程图）。  
旁路：`问题清单.md`。不要把问题写进正式三件或附图。交付回复末块须为 **`## 交付后请确认`**（见 `issues.md`）。

不做：请求书、费减、序列表、发明人签章、XML/CPCNS 客户端包、TIFF、海外申请。  
不评价新颖性 / 创造性 / 授权。

## 输入

必须是同案交底产出：

- 交底书（时间戳 `.md`，有则兼用 `.docx`）
- 发明：交底正文（框图/流程在 mermaid 里）
- 实用新型：`structure_schema` + `figure_plan` + 入文线稿
- 外观：`appearance_schema` + `figure_plan` + 入文实拍/线稿

仅**缺文件**时终止。公式写法、平局规则、从属是否过窄等，选定交底能支撑的一种继续写，记入问题清单。

## 主文件纪律

- 正文用申请书式，不要写「草稿」「须人改」「待确认」、质量分、仓库脚注、检索说明、来源 URL
- 背景技术为叙述性（公布文本惯例），**不排公布号列表**、不写检索说明、URL、数据库名。交底第一章有明确最近对比件时，可**点名一件写透**（写清它做了什么、针对本发明缺什么），如无则用「领域现状 → 已有做法 → 然而/首先/其次/再次 → 上述缺陷导致」的叙述推进；缺口必须对上交底第二章的技术问题。结构正例见 `specification_builder.md`。
- 发明内容为问题、独立方案、按从属树展开的必要从属要点、有益效果
- 发明方法权要写法**两式择优，选定后全稿同口径**（计 `claim_style`）：
  - **编号式（默认）**：独权「包括如下步骤：步骤1，…；步骤2，…」，附图与实施例共用同一套步骤号，流程图框内与独权步骤**逐字同义**；流程图不拉引出线，不另标 201、202。机器可校验（`check_support` 步骤对照）。
  - **不编号式**：独权特征由分号连接不编号（如只需与交底公布稿同款时），实施例用「S1、S2…」并与流程图框内文字同义对应；须在 `application_plan.yaml` 记 `claim_style: unnumbered`，步骤机械对照自动跳过，交付前人工核同义。
  - 两式**不得混用**：权要编号而实施例用 S1（或反之）视为不一致。
- 发明系统/模块独立权项只写模块名称，**不**写（10）（20）；系统框图框内写名称，**不**标件号、**不**拉引出线
- 实用新型结构图仍用件号与引出线（与 `structure_schema.parts` 同一张表）；申请附图须黑白紧裁，不得直接用交底彩色原图
- 外观视图按 `design_view_cnipa.md` 核查，并跑本包 `check_design_views.py`；原样引用交底入文图，不升格、不改像素；漏视/虚线/新事项写入 `视图检查清单.md`，摘要进问题清单
- 公式、符号、交底已有的多行对照/参数表默认写在说明书具体实施方式；表题「表1」起编号，不进权要、不当附图。交底已有表不得改成一段叙述；交底没有的表不要编。权要只保留审查必须卡住的计算关系，整式不要塞进权要。交底有 `formula_plan.yaml` 则说明书与权要文字关系与之同义
- 摘要不超过 300 字，无宣传语，摘要附图默认主流程图
- 附图黑白线框；图号写在说明书正文，不要画进图里；PNG 按内容包围盒截取。用户点名或交底已入文的场景图可作 `source_image`，不扫工程素材、不承诺重画
- 交底 mermaid 彩色 PNG 只当结构来源，不得当作说明书附图
- 已有申请产出上改稿：新时间戳目录，不覆盖旧目录

## 禁止

- 未指定交底目录就开写；材料缺失仍继续
- 从聊天空写申请
- 宣称已通过国知局附图审查或电子申请格式校验
- 外观案套用发明权要
- 外观案用 `compose_application_figure.py` 改交底原图，或为省略面默补假面
- 自动堆装置 / 介质 / 系统权要（交底第五章没有对应对象就不写）
- 扫描前端或工程素材目录当附图
- 覆盖上一版申请产出目录（用户明确要求覆盖除外）
