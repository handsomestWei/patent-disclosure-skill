# 申请文件 · 说明书与摘要

> 句式与语言参照 `references/专利语句库.md`（句式库/词库/附图标记规范）。

交底提供技术方案事实与可实施方案。按申请书式写五部分。附图已按 `figures.md` 画出后再写「附图说明」，嵌入 `figures/图N.png`。

材料出处见 `references/disclosure_to_spec_map.md`。从属层与「第一种/第二种」实施例对齐，见 `claim_strategy.md`。

## 五部分

| 部分 | 写法 |
|------|------|
| 技术领域 | 一句：本发明涉及…，属于…技术领域。 |
| 背景技术 | 叙述性：领域现状 → 已有做法 → 然而缺口（对上交底第二章）。交底有明确最近对比件时可点名一件写透，无则纯叙述推进。禁止检索说明、分组综述、来源 URL、数据库名、「经检索」、公布号列表。结构正例见下。 |
| 发明内容 | 针对上述问题 → 独立方案（与独权同序；编号式沿用「步骤1，…」，不编号式沿用权1特征句）→ 必要从属要点按从属树「进一步」简述 → **有益效果**单独成段，效果须能对上手段。系统方案用模块名。 |
| 附图说明 | 「图1为…示意图；图2为…示意图。」点名场景图同样列「图N为…示意图」。框图不列（10）释义。插图用 `![图N](figures/图N.png)` |
| 具体实施方式 | 结合附图把主方案**与权要同口径**走通：编号式用「步骤1、步骤11」；不编号式用「S1、S2…」与独权特征句同义对应。`claim_tree` 里 `aligns_embodiment: 第一种` 的从属在第一种实施例展开；`第二种` 对应分支。公式、符号、数值例、交底已有表格写在这里。交底没有的硬件细节不要编。 |

### 背景技术（叙述，不要检索列表）

Markdown 里不要手写 `[0002]` 段号（客户端/排版会加）。结构按公布稿惯例两式择优，**不得排成公布号列表**：

**写法一 · 叙述式（默认）**：领域现状 → 已有做法（行业惯例/技术路线，不带公布号）→ 然而/首先/其次/再次 → 缺口对上交底第二章。

> 在{领域}，{现象}是常见的{问题}。当前，对于{对象}已有较多研究，国内外学者提出了多种基于{参数}的{体系}。例如，采用{方法1}、{方法2}等{单指标/多指标}综合评判的方法，对{对象}进行{预测/分级}。
>
> 然而，{现有做法}仍存在诸多不足：首先，{不足1}；其次，{不足2}；再次，{不足3}。上述缺陷导致难以实现{目标}，{后果}。

**写法二 · 点名一件写透**：交底第一章**明确记载**了最接近的对比件（有公布号）时可用。同样一段写清它实际做了什么、针对本发明缺什么；如果还存在另一类手段明显不同的常规做法，可再加一段叙述它为何仍解决不了问题。

> 中国专利申请（公布号：CNxxxxxxxxA）公开了一种{对象}，由{谁}根据{条件}确定{做法}，用以{目的}。
>
> 上述方案主要用于{场景}，但没有公开如何{本发明的关键手段}，也难以{技术问题}。

两种写法的**共同铁律**：

1. 缺口必须对上交底第二章的技术问题，不要空泛「效率不高」。
2. 不要写「在某数据库检索得到 CN1×××、CN2×××」（检索腔）；不要连续罗列三件公布号各写两句（查新摘录腔）。
3. 具体实施方式的正反例见 `references/撰写任务流程.md`；真实公布文本样例（叙述式背景、双式步骤编号）可对照 `5篇公布文本风格总结.md`。
4. 尾句「本背景技术……不构成现有技术的信息」**可选**，公布文本不强制；默认不写。

实用新型用「本实用新型」。正式说明书不要写问题清单。

## 表格

表格不是法定必需要件。交底里**已有**多行同结构数据（参数清单、对照实验、配置/覆盖对照等）时，说明书**必须保留表形态**，不得收成「本实施例中可取…」一段。

- 正文先点题（如「具体校验结果见表1」），再写 Markdown 表；表题用「表1」「表2」，按实施例出现顺序编号
- 表放说明书正文，**不**当附图、**不**进权要
- 实施例取值在表下加一句：上述数值仅为实施例，不作为权利要求限制
- 交底只有一两处零散数字：用「本实施例中」叙述，不要为了像公布稿而造表
- 交底没有的行、列、实验结论不要编；有表漏搬则记问题清单

## 公式

交底目录有 `formula_plan.yaml` 则 **`Read`** 后写入具体实施方式：先符号表，再只展开计划中的式，数值例与计划 `numeric_example` 或表 N 一致。权要只保留文字关系。计划没有的主式不要编。

## 摘要（`说明书摘要.md`）

- 结构：技术领域一句 + 现有不足一句 + 手段（与独权同序的要点）+ 效果一句。不要背景展开、不要权利要求编号、不要宣传语（词库 `references/promo_terms.yaml`）。
- 文字部分一般**不超过 300 字**（汉字与字母数字合计，不含图）。超了先删背景与效果形容词。
- 摘要附图：`figures/摘要附图.png`，默认主流程图，与 `suggested_abstract_figure` 一致。

## Word

```bash
python skills/patent-application/tools/emit_application_docx.py --dir <产出目录>
```

公式尽量 OMML；失败记问题清单，仍出 Word。

**行内公式必须写 `\(…\)`**（或全文统一 `$…$`），**禁止**用普通括号包 LaTeX（`(M_{\mathrm{total}})` 在 Word 里是纯文本，常带拼写红线）。Markdown 预览把 `\(` 显示成 `(`，勿据此删反斜杠。`emit_application_docx.py` 遇命中会对该文件打印 **`DOCX: ok=0 reason=latex_delim`** 并**跳过写出**；须改分隔符后再重跑。定稿前可单独跑：

```bash
python skills/patent-application/tools/latex_delimiters.py -i <产出目录>/说明书.md
```
