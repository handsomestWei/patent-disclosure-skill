# 申请文件 · 权利要求书

先有 `application_plan.yaml` 的 `claim_tree`。正式权要里禁止待确认标记、质量分。

1. 先独立权利要求 1，再按 `claim_tree.dependents` 的 `id` 顺序写从属。「……，其特征在于……」。独立权项不引用其他权项；从属只引用在先权项。
2. 实用新型件号与 `structure_schema.parts` 同一张表。
3. 发明方法独权用「包括以下步骤：」+「步骤一，…；步骤二，…」。权利要求 1 每个「步骤N，…」必须与 `invention_figures.yaml` 流程图节点 `label` **逐字同义**（脚本按子串对照，对不上会报 `STEP_MISMATCH`）。匹配分构成、双阈值含义、窗口长度等细节只进从属，不要写进权利要求 1。不要另编 S1 或 201。从属展开某步时用「步骤一…的方法如下：」「步骤11」这类嵌套，仍不要改用 S1。
4. 发明系统独立权项只写模块名称及连接/功能关系，**不**写（10）（20），**不**与引出线对齐。第二条「一种…系统 / 装置」独立权项不要写成从属。
5. 计算公式默认放说明书。从属用文字限定计算关系（「按…加权并扣除…得到匹配分」），不要把整段 LaTeX 写进权要。交底有 `formula_plan.yaml` 时：权要用语须与计划中的符号含义同义，式面只在说明书。
6. 去掉宣传语（词库 `references/promo_terms.yaml`）。效果放说明书有益效果与实施例。参数表、对照表只写说明书，不要写进权要。
7. 「所述」须有前置：该词在本项更早位置或在先引用权项中已出现。不要一上来就「所述匹配分」。
8. 非中文技术名词与说明书同词；权要集内**第一次**写成「中文全称（缩写）」（如中央处理器（CPU）），其后用「所述CPU」。不要每项从属再展开，不要写英文全称。

分份：`权利要求书.md`。

```bash
python skills/patent-application/tools/audit_claims.py <产出>/权利要求书.md
```

`APPLICATION_CLAIMS: ok=0` 时先改权要再写说明书。警告写入问题清单，不阻塞。机器通过不等于授权。
