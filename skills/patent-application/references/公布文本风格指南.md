# 专利文本撰写风格指南（依据 CNIPA 发明公布文本）

> 来源：已下载 21 篇发明公布 PDF（重点参考 CN122949635A《时滞性岩爆分级预警方法及系统》、CN120083446A《基于电脉冲技术的凿岩钻杆及其使用方法》）。
> 用途：作为「调整专利文本表述」的任务流程——先看部分结构，再看每部分风格句式，最后按流程执行。
> 定位：本指南忠实记录**式 B（不编号式）**样例；编号式（权要「步骤1，…」如 CN119686739A）见 `claims_builder.md` / `撰写任务流程.md`。两式按 `application_plan.claim_style` 择优，跟 prompts 冲突处以 prompts 为准。

## 一、文本部分结构（发明申请公布稿）

```
著录项目：(19)(12)(10)(43)(21)(22)(71)(72)(74)(51)(54)(57)   ← 非撰写内容，代理人/系统填
(54)发明名称
(57)摘要                        ← 300字内，一句领域+一句现有不足+手段+效果
权利要求书（权利要求书N页）       ← 独立权利要求1 + 从属，从属引用在先权项
说明书：
  技术领域      [0001]
  背景技术      [0002]-[0003]   ← 叙述性，不点名对比文件
  发明内容      [0004]-[00xx]   ← 目的+技术方案（第一/第二方面）+优选方案+有益效果
  附图说明      [00xx]          ← 为了更加清楚地说明...图1...；图2...
  具体实施方式  [00xx]-[结尾]    ← 结合附图+实施例+S1/S2步骤编号
说明书附图（图1...图N）
```

**段号 [0001] 等由排版系统自动生成，撰写时只写正文，不手写段号。**

## 二、各部分风格与句式

### 1. 摘要 (57)

**结构**：技术领域一句 + 现有不足一句（可选）+ 技术手段（与权利要求1要点同序，用"包括/用于/根据"）+ 效果一句。

**典型句式**：
- `本发明公开了一种XXX方法及系统，属于XXX技术领域，方法包括：...；...。本发明能够XXX，提升了XXX。`
- 手段用分号连接，不用步骤编号。

**语言**：客观、无宣传语、无权利要求编号。≤300字（汉字+字母数字）。

### 2. 权利要求书

**独立权利要求（方法）**：
```
1.一种XXX方法，其特征在于，包括：
获取XXX；
根据所述XXX计算XXX；
将所述XXX与预设的XXX阈值进行比对，根据比对结果确定XXX；
输出XXX。
```
- **过渡语**：`其特征在于，包括：`（方法）；`其特征在于，包括：`（系统，模块列举）。
- **手段用分号 `；` 连接，步骤不编号**（区别于具体实施方式的 S1/S2）。
- 模块化系统独权：`一种XXX系统，其特征在于，包括：XXX模块，用于...；XXX模块，用于...；`。
- 从属：`2.根据权利要求1所述的方法，其特征在于，所述XXX包括：...；` / `在所述...的步骤中，...包括：...`。

**语言**：`所述`须有前置；`用于`表功能；`预设的`表阈值；`根据...确定`；`配置为/被配置为`。避免"能够/可以/有效/显著"等效果词（效果放说明书）。

### 3. 技术领域

**句式**：`本发明属于XXX技术领域，具体涉及一种XXX方法及系统。`

### 4. 背景技术

**叙述性（不点名对比文件）**：
- 第1段：`在XXX领域，XXX是...。当前，对于XXX已有较多研究，国内外学者提出了...。例如，采用XXX、XXX等单指标或多指标综合评判的方法，对XXX进行...。在XXX方面，XXX技术广泛应用于...。`
- 第2段（然而/不足）：`然而，XXX是指...。这类XXX...。对于XXX，现有的评价方法仍存在诸多不足：首先，...；其次，...；再次，...。上述缺陷导致难以实现...。`

**语言**：客观叙述现有技术做法（"已有较多研究""例如，采用...的方法""广泛应用于"），用"然而/首先/其次/再次/上述缺陷导致"推进，**不出现"中国专利申请CNxxx公开了"的点名写法**（那是审查/对比文件口径，不是公布文本）。

### 5. 发明内容

**句式序列**：
```
[目的] 本发明的目的在于针对上述现有技术中的问题，提供一种XXX方法及系统，通过...。
[方案] 为了实现上述目的，本发明有如下的技术方案：
       第一方面，提供一种XXX方法，包括：...；...；...；
       作为一种优选的方案，...；
       第二方面，提供一种XXX系统，包括：...；...；
       作为一种优选的方案，...。
[效果] 相较于现有技术，本发明至少具有如下的有益效果：...。
```

**语言**：目的句用"本发明的目的在于针对上述现有技术中的问题"；方案用"第一方面/第二方面"+"提供一种...包括："；优选用"作为一种优选的方案"；效果用"相较于现有技术，本发明至少具有如下的有益效果"。

### 6. 附图说明

**句式**：
```
为了更加清楚地说明本发明实施例的技术方案，下面将对实施例中所需要使用的附图作以简单地介绍，应当理解，以下附图仅示出了本发明部分实施例，对于本领域普通技术人员来讲，在不付出创造性劳动的前提下，还可以根据这些附图获得其他附图。
图1  本发明实施例XXX方法流程图；
图2  本发明实施例XXX系统结构示意图。
```

### 7. 具体实施方式

**句式序列**：
```
下面将结合本发明实施例中的附图，对本发明实施例中的技术方案进行清楚、完整地描述，显然，所描述的实施例仅仅是本发明一部分实施例，而不是全部的实施例。基于本发明中的实施例，本领域普通技术人员还可以在没有做出创造性劳动的前提下获得其他实施例。
[实施例1] ...请参阅图1，本发明实施例提出一种XXX方法，包括：
S1、获取XXX；
S2、根据所述XXX计算XXX；
S3、...；
S4、...。
在一种可能的实施方式中，步骤S1所述XXX包括...。
进一步的，步骤S3...具体包括：...。
[实施例2] 请参阅图2，本发明另一实施例还提出一种XXX系统，包括：...。
[结尾] 最后应当说明的是：以上实施例仅用以说明本发明的技术方案而非对其限制，尽管参照上述实施例对本发明进行了详细的说明，所属领域的普通技术人员应当理解：依然可以对本发明的具体实施方式进行修改或者等同替换，而未脱离本发明精神和范围的任何修改或者等同替换，其均应涵盖在本发明的权利要求保护范围之内。
```

**语言**：实施例内**步骤用 `S1、S2、...` 编号**（区别于权利要求书的不编号）；"在一种可能的实施方式中""进一步的""请参阅图N""最后应当说明的是"。

## 三、专利文本常用句式和语言（词库）

| 用途 | 常用表达 |
|------|----------|
| 领域句 | 本发明属于...技术领域，具体涉及... |
| 背景推进 | 在...领域，...是...。当前，对于...已有较多研究...。例如，采用...的方法...。 |
| 不足推进 | 然而，...。这类...。首先，...；其次，...；再次，...。上述缺陷导致...。 |
| 目的句 | 本发明的目的在于针对上述现有技术中的问题，提供...。 |
| 方案引导 | 为了实现上述目的，本发明有如下的技术方案： |
| 分方面 | 第一方面，提供一种...方法，包括：...；第二方面，提供一种...系统，包括：...。 |
| 优选 | 作为一种优选的方案，...。 |
| 效果 | 相较于现有技术，本发明至少具有如下的有益效果：...。 |
| 附图引 | 为了更加清楚地说明本发明实施例的技术方案，下面将对...附图作以简单地介绍...。 |
| 实施例引 | 下面将结合本发明实施例中的附图，对...技术方案进行清楚、完整地描述...。 |
| 步骤编号 | 具体实施方式用 S1、S2...；权利要求书不编号（用"包括：...；"） |
| 实施方式 | 请参阅图N，本发明实施例提出一种...方法/系统。 |
| 实施变体 | 在一种可能的实施方式中，步骤S1所述...。进一步的，步骤S3...具体包括：...。 |
| 收尾 | 最后应当说明的是：以上实施例仅用以说明本发明的技术方案而非对其限制...均应涵盖在本发明的权利要求保护范围之内。 |
| 功能词 | 所述、用于、预设的、根据...确定、获取/计算/比对/输出、配置为、包括、其特征在于 |
| 避免词 | 能够/可以/有效/显著/性能优异/发明人认为/经检索/数据库名/URL |

## 四、撰写任务流程（执行顺序）

1. **摘要**：领域句 + 手段（与权利要求1同序，分号连接） + 效果句，≤300字。
2. **权利要求书**：独权1"其特征在于，包括："（方法/系统，分号连接，不编号）→ 从属"根据权利要求N所述...，其特征在于..."。
3. **技术领域**：`本发明属于...技术领域，具体涉及...`。
4. **背景技术**：叙述现有技术做法 + 然而/首先/其次/再次 + 上述缺陷导致；**不点名对比文件**。
5. **发明内容**：目的句 → 技术方案（第一/第二方面，包括：...）→ 优选方案 → 有益效果（相较于现有技术...）。
6. **附图说明**：为了更加清楚地说明...图1...；图2...。
7. **具体实施方式**：结合附图 → 实施例1（S1/S2步骤编号）→ 实施变体（在一种可能的实施方式中/进一步的）→ 实施例2系统 → 结尾（最后应当说明的是...）。
8. **核对**：权利要求书/说明书/摘要表述一致；效果对上手段；无宣传语；所述有前置。

## 五、执行说明

- 本指南描述的是**式 B（不编号式）**的公布文本风格：权要分号连接不编号、实施例 S1（样例 CN122949635A）。实际撰写按 `application_plan.claim_style` 两式择优：交底/参照文本更接近编号式（如 CN119686739A「步骤1」）时走 `prompts/claims_builder.md` 的 numbered 口径。
- 调整既有交底或旧稿文本时，先读 `prompts/specification_builder.md` 与本指南再动笔，改完跑 `audit_claims.py`（权利要求书结构）+ `check_support.py --dir <产出>`（权要/说明书/附图对照）确认不报错。
- 附图（流程图/框图/示意图）保持现有黑白线稿；流程图节点文字随 `claim_style`；权利要求书无步骤编号时（式 B）check_support 跳过步骤匹配，改人工核同义。
- 生成 docx 前用 `latex_delimiters.py -i 说明书.md` 检查公式分隔符。
