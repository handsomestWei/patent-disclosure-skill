# 申请文件 · AI 技术方案的实施细节

按需查阅，不是权要策略的必经步骤。仅在下列情形 **`Read`** 本文：

- 用户点名 AI 实施细节、模型输入输出、训练步骤等
- 当前为发明分案，且交底材料本身是模型或智能体参与的技术方案

普通发明申请即使涉及 AI，未点名也不读本文。

把交底已披露的技术处理链贯通到权要、实施例和附图。先判断技术贡献是**模型在技术场景中的应用**，还是**模型构建或训练**，也可以两者兼有。

- **模型应用**：写明技术场景、采集对象和输入字段，如何构造模型输入、模型输出的结构，以及输出如何用于后续技术处理。实施例用一组已披露或经发明人确认的示例数据走通输入、输出及其内在关系。若模型输出参与状态更新，核对证据关联、输出校验、接受条件和失败路径中哪些属于已披露的必要手段。
- **模型构建或训练**：按技术贡献核对实现所需的模块或层级、连接关系、训练步骤与参数。模型品牌、提示词模板、阈值等仅在交底支持且与技术手段相关时采用。

交底**已经披露**下列手段时才写，不要从样例补进当前案件：

- **领域本体**：分别定义类型、属性和关系的语义约束，以及承载具体实体和关系的实例。用已披露的映射或关联规则写清原始数据到实例的过程。
- **多智能体与人工反馈**：若协作本身构成技术手段，写清各参与方读写的数据、消息或触发条件、校验与写回责任。用一个实施例贯通反馈对象、处理条件、更新内容和可追踪结果。

从交底的必要特征和优选特征分别组织独权和从属。将技术效果落到可核对的输出或指标，例如输出结构是否可校验、失败路径是否闭合。无实测数据时说明机制与预期效果，把缺少的输入、规则或验证条件列入 `问题清单.md`。发明人新补、但原申请未记载的事实单独记录，不写入分案权要。

依据：《专利审查指南》第二部分第九章 6.3.1（局令第84号，施行日 2026-01-01）。
