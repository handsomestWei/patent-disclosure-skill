# 专利文本撰写任务流程（可直接执行版）

> 依据 CNIPA 发明公布文本风格（参考 CN122949635A/CN120083446A/CN122987292A 等 5 篇）沉淀的章节任务流程。
> 用法：撰写申请文本时，按本流程逐节填写，语句库直接复制改写。**与 `prompts/` 冲突时以 prompts 为准**：权要与实施例编号按 `application_plan.claim_style` 两式择优、全稿同口径（numbered=步骤N贯通 / unnumbered=权要不编号、实施例 S1）；背景以叙述式为默认，交底明确记载最近对比件时可点名一件写透。

---

## 〇、总体思路（用户写作方法，7 步）

1. **章节结构分解**：技术领域 / 背景技术 / 发明内容 / 附图说明 / 具体实施方式 / 权利要求书 / 摘要。
2. **确定每部分意图与核心信息（核心句）**：这一节要表达什么、要让读者/审查员得到什么信息。
3. **按核心句组织叙述逻辑**：先用什么引、再推进什么、最后收到什么。
4. **分析每部分用语风格与常用句**：用语句库的句式模板。
5. **完成文本撰写**：逐节填入。
6. **完成一个章节后整体通读**，调整有问题的语句（语句通顺、逻辑、术语一致）。
7. **完成整个专利文本后再通读微调**（一致性、无宣传语、所述前置、效果对手段）。

---

## 一、章节结构 · 意图 · 核心信息 · 叙述逻辑

| 章节 | 意图（要表达什么） | 核心信息（核心句） | 叙述逻辑 |
|------|-------------------|-------------------|----------|
| 技术领域 | 划定技术领域便于分类 | 本专利所属领域 + 方案对象 | 一句定位 |
| 背景技术 | 交代现有技术做法及其不足，引出要解决的问题 | ①现有做法有哪些 ②缺什么 | 领域现状 → 现有做法举例 → 然而/首先/其次/再次 → 上述缺陷导致 |
| 发明内容 | 公开完整技术方案 + 有益效果 | ①目的 ②技术方案（必要特征）③效果 | 目的句 → 方案引导 → 第一方面（方法）→ 优选 → 第二方面（系统）→ 效果 |
| 附图说明 | 附图索引，便于理解 | 图号 + 图名 | 为了更加清楚地说明 → 图1…；图2… |
| 具体实施方式 | 给出可实施的具体方案（实施例） | 结合附图走通步骤/系统构成 | 开场 → 请参阅图N 实施例1（编号随 claim_style）→ 实施变体 → 实施例2 系统 → 收尾 |
| 权利要求书 | 限定保护范围 | 必要技术特征（独权）+ 优选（从属） | 独权1（包括：）→ 从属（所述…为/包括） |
| 摘要 | 内容概述（审查/检索用） | 领域 + 手段 + 效果 | 一句式，≤300 字 |

## 二、各部分撰写要点（意图 → 核心句 → 逻辑 → 句式模板）

### 1. 技术领域
- **核心句**：本发明属于{领域}技术领域，具体涉及一种{方案对象}。
- **模板**：`本发明属于{领域}技术领域，具体涉及一种{方案对象}。`

### 2. 背景技术（叙述性，不点名对比文件）
- **核心句①**：现有技术有哪些做法。
- **核心句②**：这些做法缺什么（必须对上发明内容的技术问题）。
- **模板**：
```
在{领域}，{对象}是{现象/问题描述}。当前，对于{对象}已有较多研究，国内外学者提出了多种基于{参数}的{体系}。例如，采用{方法1}、{方法2}等{单指标/多指标}综合评判的方法，对{对象}进行{预测/分级}；或采用{综合评价方法}，将多指标加权得到{结果}。在{方面}，{技术}广泛应用于{用途}。
然而，现有的{对象}…仍存在诸多不足：首先，{不足1}；其次，{不足2}；再次，{不足3}。上述缺陷导致难以实现{目标}，{后果}。
```
- **注意**：不出现"中国专利申请CNxxx公开了"点名写法；缺口对上发明内容问题；避免空泛"效率不高"。

### 3. 发明内容
- **核心句①**：本发明的目的（解决什么问题）。
- **核心句②**：技术方案（必要技术特征，与权利要求1一致）。
- **核心句③**：有益效果（对上手段）。
- **模板**：
```
本发明的目的在于针对上述现有技术中的问题，提供一种{方案对象}，通过{关键手段}。
为了实现上述目的，本发明有如下的技术方案：
第一方面，提供一种{方案对象}，包括：
{步骤1}；
{步骤2}；
{步骤3}。
作为一种优选的方案，{优选限定}。
第二方面，提供一种{系统对象}，包括：
{模块1}，用于{功能}；
{模块2}，用于{功能}。
作为一种优选的方案，{系统优选}。
相较于现有技术，本发明至少具有如下的有益效果：{效果1}；{效果2}；{效果3}。
```
- **注意**：方案与权利要求1同序；效果须能对上手段（手段→效果一一对应）。

### 4. 附图说明
- **模板**：
```
为了更加清楚地说明本发明实施例的技术方案，下面将对实施例中所需要使用的附图作以简单地介绍，应当理解，以下附图仅示出了本发明部分实施例，对于本领域普通技术人员来讲，在不付出创造性劳动的前提下，还可以根据这些附图获得其他附图。
图1  本发明实施例{图1名}；
图2  本发明实施例{图2名}。
```

### 5. 具体实施方式
- **核心句**：结合附图走通方法步骤，编号口径随 `claim_style`：numbered 用与权要同一套「步骤1/步骤11」；unnumbered 用 S1、S2 与权要特征句同义。
- **模板**：
```
下面将结合本发明实施例中的附图，对本发明实施例中的技术方案进行清楚、完整地描述，显然，所描述的实施例仅仅是本发明一部分实施例，而不是全部的实施例。基于本发明中的实施例，本领域普通技术人员还可以在没有做出创造性劳动的前提下获得其他实施例。
请参阅图1，本发明实施例提出一种{系统}，包括：{模块1}、{模块2}、{模块3}。{连接/功能关系一句}。
请参阅图2，本发明实施例提出一种{方法}，包括：
步骤1、{步骤1}；
步骤2、{步骤2}；
步骤3、{步骤3}；
步骤4、{步骤4}。
在一种可能的实施方式中，步骤1所述{限定}。
进一步的，步骤3…具体包括：{展开}。
在一种可能的实施方式中，步骤4…{限定}。
{实施例2 数值例：}某{场景}，{参数}取{数值}，计算得{结果}，达{等级/效果}。技术效果：{效果}。上述数值仅为实施例，不作为权利要求限制。
最后应当说明的是：以上实施例仅用以说明本发明的技术方案而非对其限制，尽管参照上述实施例对本发明进行了详细的说明，所属领域的普通技术人员应当理解：依然可以对本发明的具体实施方式进行修改或者等同替换，而未脱离本发明精神和范围的任何修改或者等同替换，其均应涵盖在本发明的权利要求保护范围之内。
```
- **注意**：编号口径与 `claim_style` 同口径——numbered 全稿「步骤1、步骤11」（如 CN119686739A），unnumbered 全稿权要不编号、实施例 S1（如 CN122949635A），两式不得混用；不要把流程图画成引出线加 201。实施例数值例"上述数值仅为实施例，不作为权利要求限制"。

### 6. 权利要求书
- **核心句**：必要技术特征（独权）+ 优选特征（从属）。
- **模板**：
```
1.一种{方案对象}，其特征在于，包括：
{必要特征1}；
{必要特征2}；
{必要特征3}。
2.根据权利要求1所述的方法，其特征在于：{优选限定}。
3.根据权利要求1所述的方法，其特征在于：{分支/回环限定}。
…
N.一种{系统对象}，其特征在于，包括：
{模块1}，用于{功能}；
{模块2}，用于{功能}。
```
- **注意**：独权两式择优并与 `claim_style` 一致：numbered 用"其特征在于，包括如下步骤：步骤1，…"；unnumbered 用"其特征在于，包括："分号连接不编号（如 CN122949635A）。从属引用「根据权利要求1或2所述」多引合法；`所述`须有前置；无效果词（能/可以/有效/显著）；效果图放说明书；系统独权只写模块名+连接/功能关系，不写附图标记。

### 7. 摘要
- **核心句**：领域 + 手段 + 效果。
- **模板**：`本发明属于{领域}技术领域，公开了一种{方案对象}。{手段，与权1同序}。本发明能够{效果}。`
- **注意**：≤300 字（汉字+字母数字）；无背景展开、无权利要求编号、无宣传语。

## 二B、专利附图撰写规范

### B1. 专利常用图类型（黑白线条）

| 图类型 | 内容 | 对应权项/章节 | 标记方式 |
|--------|------|--------------|----------|
| **流程图** | 方法步骤（编号随 `claim_style`：「步骤N」或无编号特征句），与独权同序同义 | 发明方法独权 / 发明内容、具体实施方式 | 框内写对应文字，**不拉引出线** |
| **架构图（框图）** | 系统模块关系（模块名），虚线分组 | 发明系统独权 / 发明内容、具体实施方式 | 框内模块名，**不标（10）（20）**、不拉引出线 |
| **结构图** | 装置结构（剖视/装配/分解），件号标注 | 实用新型 / 装置发明 / 具体实施方式 | 件号（10）（20）…，与说明书**同一张表** |
| **示意图** | 场景/拓扑/布置/对照（如装置布置、应力区） | 具体实施方式实施例 | 可标注对象名，可读即可 |
| **数据图** | 实验曲线/柱状（可选） | 实施例数据 | 坐标轴+图例，黑白 |

### B2. 图一律黑白线条

- 申请附图一律**黑白**（线条+文字），无彩色、无灰度照片、无阴影填充；
- 线条清晰、字体规范（黑体/宋体），标注可读；
- 背景白底，不用彩色区分（需区分用线型/线宽/图案填充）。

### B3. 图标记

- **图号**：图1、图2…按出现顺序，写在说明书「附图说明」与插图下方正文，**不画进图内**；
- **图名**：`本发明实施例{图名}示意图`；
- **附图标记（件号）**：结构图用（10）（20）…，说明书须同一张表（件号-名称）对应，**框图/流程图不标件号**；
- **摘要附图**：主流程图（或主图），用于摘要。

### B4. 类型-章节-内容-图对应

| 专利类型 | 章节 | 内容 | 配图 |
|----------|------|------|------|
| 发明（方法） | 发明内容/具体实施 | 方法步骤 | **流程图** |
| 发明（系统） | 发明内容/具体实施 | 系统模块 | **架构图** |
| 发明（方法+系统） | 发明内容/具体实施 | 步骤+模块 | **流程图+架构图** |
| 装置发明 | 具体实施方式 | 装置布置 | **示意图** |
| 实用新型 | 具体实施方式 | 装置结构 | **结构图**（件号） |
| 任何 | 附图说明 | 图索引 | 附图说明文字（图1…；图2…） |
| 任何 | 摘要 | 摘要附图 | 主流程图/主图 |

### B5. 撰写要点

- **流程图**：框内写与 `claim_style` 对应的文字（numbered：步骤N；unnumbered：权要特征句），与独权同序同义；主流程图框数=方法独权步骤数；分支、回环只写从属/实施例，不在独权图上另编；
- **架构图**：虚线分组+框内模块名（与系统权项/说明书同一套名称），不标件号、不拉引出线；
- **结构图**：件号与说明书同一张表，黑白线稿；
- **示意图**：场景/布置，标注对象名，可读；
- 图号只写在正文，不画进图；黑白；不凑套图（权要没写到的剖视/爆炸不画）。

## 三、语句库（通用句式 / 常用词）

### 3.1 句式库（按用途）

| 用途 | 句式 |
|------|------|
| 领域句 | 本发明属于{领域}技术领域，具体涉及一种{方案对象}。 |
| 背景引 | 在{领域}，{对象}是{现象}。当前，对于{对象}已有较多研究…。例如，采用{方法}的方法…。 |
| 不足推进 | 然而，现有的{对象}…仍存在诸多不足：首先，…；其次，…；再次，…。上述缺陷导致难以实现{目标}，{后果}。 |
| 目的句 | 本发明的目的在于针对上述现有技术中的问题，提供一种{方案对象}，通过{关键手段}。 |
| 方案引导 | 为了实现上述目的，本发明有如下的技术方案： |
| 分方面 | 第一方面，提供一种{方法}，包括：…；第二方面，提供一种{系统}，包括：…。 |
| 优选 | 作为一种优选的方案，…。 |
| 效果 | 相较于现有技术，本发明至少具有如下的有益效果：…。 |
| 附图引 | 为了更加清楚地说明本发明实施例的技术方案，下面将对实施例中所需要使用的附图作以简单地介绍…。 |
| 实施引 | 下面将结合本发明实施例中的附图，对…技术方案进行清楚、完整地描述…。 |
| 实施变体 | 在一种可能的实施方式中，步骤1所述…。进一步的，步骤3…具体包括：…。（unnumbered 式为：步骤S1所述…） |
| 收尾 | 最后应当说明的是：以上实施例仅用以说明本发明的技术方案而非对其限制…均应涵盖在本发明的权利要求保护范围之内。 |

### 3.2 功能词 / 动词库

- **功能词**：所述、用于、预设的、根据…确定、包括、其特征在于、配置为、被配置为、至少一种、任意一种或多种的组合。
- **动作动词**：获取/采集、计算、比对/比较、确定、输出、映射、联动、判定、施加、修正、提取、归入、合成。
- **避免词**：能够/可以/有效/显著/性能优异/发明人认为/经检索/数据库名/URL（效果放说明书）；"中国专利申请CNxxx公开了"（背景叙述化）。

## 四、撰写后检查清单

| 检查项 | 方法 |
|--------|------|
| 意图达成 | 每节核心句是否完整（背景缺口对上发明内容问题；效果对上手段） |
| 跨章节一致 | 权1必要特征 = 发明内容方案 = 具体实施 S 编号（同义）；系统模块名在说明书+系统权项一致 |
| 权利要求结构 | `audit_claims.py 权利要求书.md` → `APPLICATION_CLAIMS: ok=1` |
| 说明书/附图对照 | `check_support.py --dir <产出>` → `APPLICATION_SUPPORT: ok=1` |
| 公式分隔符 | `latex_delimiters.py -i 说明书.md` → `hits=0` |
| 摘要字数 | ≤300 字（汉字+字母数字） |
| 全文通读 | 语句通顺、无宣传语、所述有前置、编号与 `claim_style` 全稿同口径（两式不得混用） |

## 五、执行顺序（撰写一页专利）

```
1. 定章节结构（技术领域/背景/发明内容/附图说明/实施/权要/摘要）
2. 技术领域（核心句）→ 填模板
3. 背景技术（核心句①做法 + 核心句②缺口）
4. 发明内容（目的 + 方案 + 优选 + 效果）
5. 权利要求书（独权 + 从属）→ audit_claims
6. 附图说明（图号 + 图名）
7. 具体实施方式（S 编号实施例 + 变体 + 收尾）→ check_support
8. 摘要（≤300 字）
9. 生成附图（flowchart/block_diagram，黑白）→ render_invention_figures
10. latex_delimiters 检查 → emit_application_docx → 全文通读微调
```

## 六、一句话总结

> 每个章节先问"我要表达什么（意图）→ 读者要得到什么（核心信息）→ 怎么讲（逻辑）"，再套语句库句式，写完一节通读一节，全文完成后整体微调。
