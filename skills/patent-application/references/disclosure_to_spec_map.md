# 交底章节 → 说明书材料来源

交底提供技术方案事实。说明书按申请书式撰写。

## 发明

| 说明书 | 从交底取什么 |
|--------|----------------|
| 技术领域 | 案件名称；第三章场景与对象（写成一句「涉及…属于…领域」） |
| 背景技术 | 第一章现有技术与缺点，叙述性（交底有明确最近对比件可点名一件写透）；丢掉检索说明、URL、分组标题，不要排成公布号列表 |
| 发明内容 | 第二章问题；第三章方案（对齐独权步骤一…与模块名）；第四章可核对的效果；第五章只约束保护范围，不要整段粘贴 |
| 附图说明 | 图序与交底 3.2 / 3.4 结构一致，外加交底已入文或用户点名的场景图；文案按申请附图（编号随 claim_style / 模块名 / 场景示意） |
| 具体实施方式 | 第六章及第三章已写清的可实施方案、公式、数值例；交底中的 Markdown/Word 表原样消化为说明书「表N」；交底 `formula_plan.yaml` 的符号与数值例写入实施例（见 `specification_builder.md`） |

## 实用新型

| 说明书 | 从交底取什么 |
|--------|----------------|
| 技术领域 | 案件名称；第三章总体构成 |
| 背景技术 | 第一章结构向现有技术与缺点 |
| 实用新型内容 | 第二章问题；3.1–3.5 与 schema.parts / relations；第四章优点；第五章装置书式保护点 |
| 附图说明 | `figure_plan` 入文 `fig` + `relates_to`（总装 / 剖视 / 爆炸 / 局部） |
| 具体实施方式 | 第六章；拆装或使用过程若在 3.4，可并入实施例，仍不要改写成方法专利。交底已有表同样消化为「表N」 |

## 外观

不走五部分发明书式。见 `prompts/design_application.md`：简要说明 + 视图选择（全线稿或全实拍）+ 实拍/线稿对应。视图按 `design_view_cnipa.md` 核查，原图不改，缺口进问题清单。
