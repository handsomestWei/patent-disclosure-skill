# 交底书生成后自检（Step 8，内部执行）

自检结果用于**修订正文**，默认**不单独输出自检报告**；用户索要时可单独提供。**不得**将自检清单作为交底书一章写入正文。

**按类型选用**：

| 类型 | 必做 |
|------|------|
| 发明 | §8.1–§8.3（全文） + **§8.7**；含公式时 §8.2 必核 |
| 实用新型 | §8.3 通用项 + **§8.4** + **§8.7**（客体组按结构类口径；§8.1–8.2 中明显属「算法/系统/公式」的条目可跳过） |
| 外观设计 | §8.3 中与命名/查新/文末清洁相关项 + **§8.5**（**不做** §8.7） |

细则成文入口：`invention|utility_model|design/disclosure_builder.md`。

## 8.1 逻辑与闭环（发明为主）

- [ ] 技术方案是否形成完整闭环（发现→处理→扩展/输出）？
- [ ] 模块之间关联关系是否清晰？上下游是否衔接？
- [ ] 分支样本（如边界样本、低置信度样本等）是否有明确处理路径？
- [ ] 依赖项（如类别中心、动态阈值等）是否有来源说明？
- [ ] **第五章「技术关键点」与第三章「系统流程」是否呼应？** 第五章以论点概述为主，技术细节在第三章；每条保护点须为可实施机制，**不是**仅罗列标题对象或「有三个××」。
- [ ] **3.1 对象与术语**：是否已按场景与参与者、标题对象如何进入系统、高频**领域词**定义三小段铺垫？
- [ ] **标题贯穿**：案件名称中的领域实词是否在 **3.2 框图、3.4 流程、第六章**作为同一执行主体出现，且未被更空的上位词替换？
- [ ] **术语贴合话题**：3.3 / 3.5 / 第五章用词，只看标题和 3.1 场景是否像本领域？若像另一技术领域（账本、指纹、水位、幂等、锚点等只是错位例，随案而变），是否已换成领域表述而非靠定义保留？机制是否仍说得清？
- [ ] **3.3 与 3.4 对应**：3.3 是否按框图拆成独立模块？3.4 正文是否逐项对应图中 S1—Sn（无漏步、无多步混成一段且不点序号）？
- [ ] **实施例**：是否有 2～3 个与 3.1/3.2 同名的实例（职责、能力、交付物、依赖），并覆盖主路径 + 一条第三章已有分支（而非 3.4 缩写）？

## 8.2 公式与参数一致性（发明；含公式时必做）

**Step 8 必做（含公式时）**：除符号体例与跨节一致外，须**主动复核公式是否正确、公式逻辑是否与第三章叙述一致**（等同用户会提出的「检查公式和公式逻辑是否有误，有误请调整」）；发现问题**直接改稿**，勿仅提示用户自行修改。

### 符号与体例

- [ ] **formula_plan（发明含公式）**：案件目录已有 `formula_plan.yaml`；每条式已标 `origin`；`source` 未改写成范式模板且有 `source_ref`（或等价出处）；source 式已标 `source_kind`（有 `.tex` 则为 `tex`，且优先对 `tex_formula_inventory.md`，成文不必再载入 `.tex`）；`verified: false` / `pdf_text` 未当作 Fk；`agent` 的 `paradigm_id`∈合并后的范式库；材料未采用的式已进 `omitted`；`check_formula_plan.py` 通过或等价手检通过
- [ ] **保真（有材料公式时）**：3.4.1 主式能否对上材料（项、算符、条件未被丢掉或换成库内简单式）？
- [ ] **符号表（3.4.1）**：全文含公式时是否已设 **3.4.1** 并 **先定义符号**（含义、下标、量纲）；式 (1) 及后文每个符号是否均已在表中定义？
- [ ] **维度下标**：是否存在 `^{cpu}`、`^{mem}`、`^{io}` 等 **上标表示维度** 的写法？若有须改为 `b_{i,\mathrm{cpu}}`、`a_{j,\mathrm{mem}}` 等 **下标 + `\mathrm{}`** 形式（见 **`disclosure_builder.md` §7.7**）
- [ ] **装饰音**：是否出现 `\tilde`/`\hat`/`\bar` 等？若有改为独立符号（如平滑量 \(A\)）或范式 `ema_smooth`
- [ ] **字母多义**：同一字母是否兼指任务侧与节点侧等不同对象？若有须拆分符号（如任务用 \(b\)、节点用 \(g\)）
- [ ] **公式表述一致**：同一物理量在不同公式、段落中是否 **同形同义**（如权重公式、调整系数、匹配分 \(s_{ij}\) 等）
- [ ] **LaTeX 体例**：行内/块级分隔符是否全文统一（`\(...\)`/`\[...\]` 或 `$`/`$$` 二选一）；块级公式是否尽量单行；是否避免 `\text{且}` 等易渲染失败写法
- [ ] **行内分隔符（硬项）**：定稿 md **不得**把含 `\mathrm` / `\,` / `_{` 的式子写成普通括号（如 `(M_{\mathrm{total}})`、`(m_{\mathrm{silica}}=60\,\mathrm{g})`）。须为 `\(…\)` 或 `$…$`。预览里 `\(` 看起来像 `(`，勿删反斜杠。跑 `python tools/latex_delimiters.py -i <定稿.md>`，有 hits **不得出 Word**；改正后对**该时间戳 md**重跑 `mermaid_render.py` / `md_to_docx.py`，禁止用未改正的 `draft.md` 出交付 `.docx`
- [ ] **3.5 与符号表**：3.5 参数表「符号」列是否与 3.4.1 **逐字同形**
- [ ] **阈值范围**：与正文一致（如 0.5–1.5、0.8–1.2 等）
- [ ] **参数命名**：全文统一，避免同义不同名混用（公式符号与 **§8.1 场景术语**分开查：场景词换名须整族替换，见 merger / correction）
- [ ] **实施例数值**：与 3.5 关键技术参数对应，不冲突；且与 `formula_plan.numeric_example` 可互相印证

### 公式正确性与逻辑（必核）

- [ ] **式面正确性**：各式是否无明显笔误（运算符、括号配对、上下标错位、同一式内符号与符号表不符、缺项/多写项、指数或分母写错等）？
- [ ] **可算性**：先跑 `python tools/check_formula_plan.py -i …/formula_plan.yaml --eval`；agent 式代算失败须改式或改数值例。source 复杂式脚本跳过则手算或从缺，**禁止**改成库内简单式以通过代算
- [ ] **量纲常理**：相加各项是否已无量纲/归一？防零除 \(\varepsilon\) 是否与分母同量纲？有无裸 `max(1, 容量)`？
- [ ] **约束与不等式方向**：公式中的 `\leq`/`\geq`/正负号是否与文字含义一致（如「饱和度」「有余量」「限频间隔」等）；多条件「且/或」是否与 3.4 流程分支一致？
- [ ] **公式与流程互推**：3.4.1 主公式（含式 (1)）及衍生式，能否与 **3.4 流程说明**（各步骤 S1—Sn）、**3.3 模块职责** 逐步对应？叙述中的打分、重排、限频、窗口聚合等是否在公式中有体现，**无**「文字一套、公式另一套」？
- [ ] **边界与特殊情形**：空队列、单节点、分母为零、指标缺失、达到上下界等情形，公式或正文是否给出合理处理或说明（至少不与主公式矛盾）？
- [ ] **量纲与取值**：符号表声明的量纲/取值范围是否与公式用法一致（如权重为正、比例在 0—1、计数为非负整数等）？
- [ ] **修订联动**：若修正公式或逻辑，是否已同步改 **formula_plan**、**3.4 文字**、**3.5 参数**、**第六章实施例** 及 **3.4.1 符号表**（见 §7.7 跨节一致）？改正 LaTeX 分隔符后，是否已用改正后的时间戳 md **重出** `.docx`（未沿用旧 Word）？

## 处理原则

发现问题则**直接修订正文**后再交付。  
**公式类（发明）**：Step 8 须完成 §8.2 核对；有误则改公式并联动修订相关章节，**不要**只向用户报告问题而不改稿（除非缺少必要技术事实、无法从正文与材料推断正确写法）。  
**术语 / 标题贯穿 / 实施例（发明）**：§8.1 相关项不通过则改 3.1、框图、流程、实施例或第五章后再交付；换叫法须整族替换，机制不丢。  
**法定要件（发明 / 实用新型）**：**§8.7** 的「三段绑定」与「删除测试」是硬项——技术问题含手段词、第五章未分必要/优选、Fk 口径各章不一致或正文靠 F 号跳转才能读懂，均须**改稿后**再交付。三态都允许成文。**不过**时禁止假 D1、禁止空喊「创新性强」；**带疑点过**须保留证据边界。按 `prior_art_search.md`「门禁」三态处理。

## 8.6 专利布局 / 专利围栏旁路（交付后，不入正文）

首篇定稿后 **`Read` `prompts/fence/guardrails.md`**，把「要不要做保护型 1+N」写进 **`## 交付后请确认` 第 3 条**（`prompts/delivery_confirm.md`），不要先打分再问。用户点名「专利布局 / 专利围栏 / 族树 / 做围栏」可强开，但仍须分解 → 突围 → 矩阵 → 立项说明。  
**禁止**未确认立项说明就批量写多篇。迭代的非首次交付默认省略第 3 条。  
**禁止**在该节把申请文件、案卷或专利地图列为下一步。
