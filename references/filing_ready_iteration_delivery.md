# 从发明探索到带风险披露的申报包

<!-- MERGE_TAG: patent-disclosure-skill/filing-ready-iteration-delivery/20260816/v1 -->

## 1. 适用范围

当任务从“继续寻找更高分发明点”转为以下任一目标时，使用本参考：

- 将既有交底书深化为代理师可直接复核的中国专利申请包；
- 同步交付项目方案说明书与专利申请文件；
- 允许披露创造性风险，但要求技术、支持、附图和文件生产达到申报标准；
- 把多个评审轮次、查新材料和项目事实增量合并为新版本；
- 为领导、研发和事务所制作可直接转发的独立子文件夹。

本参考不降低真实性、充分公开或单篇新颖性门槛；它只纠正“组合风险或内部评分不足即永远不产出”的错误停止方式。

## 2. 经验对比

| 旧行为 | 暴露的问题 | 新规则 | 触发/验收门 |
|---|---|---|---|
| 一个综合分同时决定是否继续发明和是否可以写申请 | 低分路线反复改名重启，文件交付无限后移 | 分开“发明探索门”和“文件申报门” | 冻结主线后按五项申报硬门判断，不再用综合分否定文件生产 |
| I4/I5组合风险直接触发停止 | 业务核心无法形成正式文本，风险也未进入代理师决策 | 组合风险用于收窄、分案与风险披露 | 只有单篇完整覆盖冻结最窄独权，才强制收窄或改写 |
| 把“未发现”写成“没有”，把未知写成事实 | 证据等级升级，形成支持性与真实性风险 | 资料值、推导值、设计值、待验证值分级 | 未知保持未知并给出补证方法 |
| 只围绕单一参数描述适配 | 坐标、Z、冶金、网络、光学、热史与底填差异被遗漏 | 使用多参数接口合同 | 接口域必须覆盖本案真正决定兼容性的字段 |
| 追求“任意对象”“万能适配” | 被动结构被写成可解决协议、电压或功能冲突 | 设置能力边界和失败出口 | 被动连接不能解决的冲突输出不兼容，不生成制造数据 |
| 新材料直接追加到正文 | 基线、权项、附图和风险口径漂移 | 先做五类差异，再合并 | 每项标为保留、扩写、改写、删除或仅作风险披露 |
| 只检查正文内容 | 中文方框、宽表溢出、图号冲突到收件人侧才暴露 | 文件生产纳入申报门 | OOXML、字体、PDF逐页、表格分节、图号和ZIP均检查 |
| 工作目录直接整体发送 | 内部脚本、缓存、淘汰路线与正式文件混杂 | 建立收件人导向目录 | 领导/研发/代理师入口分明，正式文件与过程材料隔离 |
| 每轮只靠时间戳 | 同一增量可能重复进入多个文件 | 使用唯一 `MERGE_TAG` | 合并前搜索tag；已存在则核验，不重复应用 |

## 3. 双门模型

### 3.1 发明探索门

用于候选路线筛选、技术证伪和查新投入决策。可使用评分、D/I/X、可实施性、业务相关性和实验门。出现单篇完整覆盖、I5且无不可拆剩余关系、技术不可实施、需要修改冻结输入对象或偏离业务目标时，可停止相应路线。

发明探索停止不自动否定已经冻结且能够充分公开的业务主案。

### 3.2 文件申报门

可使用目标状态 `FILING_READY_WITH_DISCLOSED_RISK`：申请文件技术完整、支持链和图文一致，冻结最窄独权未发现单篇完整覆盖；组合创造性、项目数据缺口和答审风险向代理师明示。

必须同时通过：

1. **充分公开**：构件、关系、步骤、输入、失败状态和实施方式完整。
2. **逐限制支持**：每个权项限制有事实或明确设计实施例，并映射到正文和图。
3. **单篇覆盖核验**：冻结最窄独权无已确认的单篇完整覆盖。
4. **法定文件一致**：说明书、权项、摘要、附图、符号与项目方案一致。
5. **真实性**：不虚构数值、结果、成本、周期、良率或可靠性。

任一门失败时，只阻断相应文件或权项并先修复可证问题；不能用文风或风险措辞掩盖结构缺失。

## 4. 增量合并协议

合并前冻结：基线和目标目录、目标状态、申请对象、独立权利要求客体、权利要求与法定附图数量、输入文件版本和页码、交付对象及 `MERGE_TAG`。

```text
MERGE_TAG: patent-disclosure/{案件短名}/{YYYYMMDDHHmmss}/{主题短名}
BASE: {基线版本或目录}
TARGET: {目标版本或目录}
STATE: FILING_READY_WITH_DISCLOSED_RISK | HOLD_FOR_FACT | BLOCKED_SINGLE_REFERENCE
```

同一tag只允许应用一次。tag写入 `交底书修订对话记录.md`、`迭代差异清单.md` 和 `版本合并摘要.md`，不得进入法定正文。

五类差异：

- **保留**：已通过支持和一致性检查的结构基线；
- **扩写**：补足接口、制造、验证、失败状态或实施细节，不改变原限制含义；
- **改写**：把抽象效果词改为可观察构件、空间关系、网络关系或步骤；
- **删除**：无事实支持、业务越界、相互矛盾或已明确淘汰的内容；
- **仅作风险披露**：强近似子结构、组合创造性压力、未完成验证或不宜进入独权的路线。

冲突事实按版本、来源和证据等级并列，不取平均、不混写成“统一规格”。

## 5. 证据阶梯与权项追溯

| 等级 | 含义 | 允许表述 |
|---|---|---|
| F | 项目签发图纸、规格、旅行单或可核验实物/测试 | 可作为项目事实，注明版本和对象 |
| D | 明确的工程设计实施例、层序、算法或制造步骤 | 写“在一实施方式中”，不得写成已实测 |
| R | 由F或D按给定公式/几何关系推导 | 写明输入、推导关系和假设 |
| U | 未知或待验证 | 保留字段、验证方法和失败出口 |
| X | 淘汰路线或仅风险材料 | 不进入主权项，只在风险说明或内部记录出现 |

缺文件不等于结构不存在，未发现单篇文献不等于确认新颖。

将每个独立权利要求拆为最小限制原子，每行至少记录：权项号和限制ID、构件/步骤、空间/网络/时序/数据关系、证据等级和来源页码、说明书段落、实施例、附图和符号、最近先案D/I/X、允许表述、禁用效果词和待补证项。

独立限制必须同时进入说明书、实施方式和附图/流程图；从属权项至少有一行支持记录。产品最终结构不能自动证明制造时序，方法事实须由旅行单、版本、设备日志或前后状态链支持。

## 6. 查新如何服务成稿

1. 冻结最窄独立权利要求后，选择有限数量最接近专利族做权项级复核。
2. 记录公开日、优先权、独权/关键实施段、来源URL及D/I/X。
3. 单篇完整覆盖全部必要限制时，收窄、改写或更换独权，不得只写风险说明。
4. 多篇组合I4/I5时，优先寻找不可拆关系、技术偏见、共同约束或反直觉边界；仍不足时进入代理师风险说明，不自动禁止文件完成。
5. 官方入口失败须记录次数和原因，按上限切换其它可核验来源；入口失败不等于“没有先案”。

## 7. 项目方案与专利文件同步深化

- 项目方案面向领导与研发，说明业务问题、接口模型、架构、设计闭环、制造、验证和失败边界；
- 交底书把项目方案转写为构件、关系、步骤、实施方式和欲保护点；
- 说明书、权项、摘要和附图只保留法定需要的信息；
- 风险说明保存组合创造性、证据等级和后续补正建议；
- 不把内部评分、淘汰路线或检索工具故障写入法定正文。

同一申请可披露多种实施架构，但已知拥挤的结构名称或普通制造时点只作实施形态，不单独冒充创造性核心。

## 8. 生产检查与收件人目录

内容检查：权利要求数量/引用/单一性、独权原子支持、材料/尺寸/网络/步骤/图号一致性，以及无证据效果词清理。

文件检查：DOCX ZIP和关键OOXML、中文可见文字、表格/公式/图片、PDF可检索和字体、逐页乱码/方框/截断/溢出/表格断裂/图号，以及ZIP可解压和文件数量一致。宽表需横向分节时，解除页眉页脚链接并核对页码。

推荐目录：

```text
00_阅读说明与结论/
01_项目方案_领导与研发/
02_专利申请文件_事务所/
03_附图与符号/
04_证据追溯与现有技术/
05_风险与后续补正/
```

排除脚本、缓存、渲染临时文件、路线试验稿、内部评分表和淘汰候选。

## 9. 可扩展接口与终止条件

后续以新 `MERGE_TAG` 扩展证据等级、权项客体、生产检查器或收件人视图；不得降低五项硬门，不得写入客户名、供应商名、保密尺寸、完整网表或测试原始数据。

完成至多两轮内容与生产检查后：

- 五项硬门通过且P0/P1为零：`FILING_READY_WITH_DISCLOSED_RISK`；
- 关键事实待补：`HOLD_FOR_FACT`，给出精确补证表；
- 冻结最窄独权被单篇完整覆盖且无法收窄：`BLOCKED_SINGLE_REFERENCE`；
- 不因“继续寻找更高分”无限延长同一版本，不把淘汰路线改名复活。
